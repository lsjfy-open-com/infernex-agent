# InferNex Agent v0.5.0-alpha.19

alpha.19 恢复普通安装的无参数 kubeconfig 自动发现。解压对应 CPU 架构的包后，普通用户运行 `sudo ./install.sh`；已经是 root 时运行 `./install.sh`。未显式指定时，安装器依次尝试合并后的 `KUBECONFIG`（合并失败时再逐文件尝试）、已安装 Agent 的配置、调用 sudo 的用户目录、实际 HOME，以及 root 和常见管理路径。不存在的常规路径会跳过；已存在但无效或无法访问 Kubernetes API 的配置会给出提示并继续。显式 `--admin-kubeconfig` 仍用于锁定目标，检查失败时立即退出，不切换到其他集群。

本版保留 alpha.18 的 Host Dashboard 直访和部署配置展示。页面中的 YAML 是 Kubernetes API 返回的当前生效对象的裁剪片段，用于现场诊断；它不等同于原始 Chart 模板、安装时的 values.yaml，也不是完整的重部署文件。

可选 SLO 对照实验以及 Git commit、配置摘要与 cluster-state snapshot 的关联记录继续保留。SLO 结果只表示已批准实验的对照结果；Git/snapshot 记录用于追溯和完整性核验，不执行生产切流或集群恢复。

安装与排查见 [Host 安装指南](https://github.com/lsjfy-open-com/infernex-agent/blob/develop/component/InferNex-Agent/docs/guides/host-install-openeuler-zh.md)，SLO 与版本记录见 [使用指南](https://github.com/lsjfy-open-com/infernex-agent/blob/develop/component/InferNex-Agent/docs/guides/slo-and-config-versions-zh.md)。
