# InferNex Agent v0.5.0-alpha.21

本版修复 Host TUI 在 full 模式下对常见集群和容器内查询反复请求批准的问题。alpha.21 安装包尚待构建与校验；alpha.20 的部署资源规划、无参数安装、Host Dashboard、SLO 对照和 Git / snapshot 记录能力继续保留。

## 本次修改

- 新增 `/mode_change root risk`：操作者显式开启后，Host 任意命令及 MCP 写操作均不逐次批准；保留真实身份、RBAC、参数和后台变更校验。模式不持久化，切回 normal 自动恢复 manual。

- 对实际命令按只读、有界诊断、集群变更和未知四类判定，支持常见 kubectl 全局参数、只读输出格式、Pod exec / SSH 查询、Helm 发布信息及只读过滤管道。
- `/mode_change root full` 或 `normal full` 下，规则识别的低风险查询自动执行。manual 仍逐次批准，身份权限和 Kubernetes RBAC 不变。
- 增加无执行副作用的命令预检工具，以及模型风险说明；模型可要求升级审批，不能把规则未确认的命令自行降级放行。实际执行前重新分类，预检不算完成任务的证据。
- 审批提示显示具体判定原因；执行结果记录规则分类、模型意见和批准方式。
- 新模块纳入双架构离线包、Host 安装及恢复点；兼容旧恢复点的清理规则，避免 TUI 缺少依赖模块。

## 边界

容器内查看日志、进程和网络状态不因使用 exec 通道而单独要求审批。full 模式中任意脚本、未知参数、重定向和命令替换仍需确认；重启、扩缩容、删除、修改路由、HCCL / iperf 压测保留审批。可回退不等于执行时不会影响业务。

root risk 为当前 TUI 会话显式取消逐次批准；后台工具的快照、资源一致性和权限校验仍保留。它没有新增原生部署写路径或自进化组件。详情见 [命令分类与审批指南](https://github.com/lsjfy-open-com/infernex-agent/blob/develop/component/InferNex-Agent/docs/guides/command-approval-zh.md)。

## 安装与验证

完成构建后提供 Linux amd64 / arm64 完整离线包与 SHA256 文件。解压后普通用户运行 `sudo ./install.sh`，root 用户运行 `./install.sh`；安装方式不要求 Helm。升级后重开 TUI，再选择 full 或明确的 root risk 模式。

发布前检查包括命令误判/绕过回归、TUI 模式与拒绝行为、Linux 身份切换、安装与恢复点兼容，以及双架构包完整性。客户真实集群的查询负载和设备工具仍需现场验证。
