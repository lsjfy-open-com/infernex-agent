# InferNex Agent v0.5.0-alpha.22

本版修复 Pi TUI 在持续工具调用中上下文达到 96% 仍不自动压缩的问题。安装包尚待构建与校验；保留 alpha.21 的命令分类、root risk、无参数安装、Host Dashboard 和既有部署规划能力。

## 修复内容

- TUI 启动时同步 `agent.conf` 的压缩阈值、上下文窗口和输出预算，开启 Pi 自动压缩；近期保留量随窗口调整，避免小窗口沿用固定 20,000 token。
- 在工具批次结束后检查有效阈值，使用 Pi 原生会话摘要压缩，再继续任务，避免持续调用工具而一直到不了整轮结束检查点。
- 压缩与自动续行协调为单次执行，防止重复压缩、重复恢复；已完成工具通过会话记录和摘要保留。
- 压缩期间补充的指令按顺序保留。失败、取消或较新的停止指令会阻止自动续行，未执行输入保留并提示重新提交。

默认百分比为 80%，同时必须预留模型最大输出空间。例如 32,768 token 窗口、8,192 输出预算的有效触发点约为 75%。已有排队指令先由 Pi 处理，下一个合适的工具边界再检查；模型或网关的窗口配置必须真实准确。详见 [上下文管理说明](https://github.com/lsjfy-open-com/infernex-agent/blob/develop/component/InferNex-Agent/docs/guides/context-management-zh.md)。

## 安装与验收

提供 Linux amd64 / arm64 完整离线包与同名 SHA256 文件。解压后普通用户运行 `sudo ./install.sh`，root 用户运行 `./install.sh`，无需 Helm；保留 kubeconfig 自动发现。升级后退出旧 TUI 并重新执行 `sudo infernex-agent chat`，让启动器同步新压缩配置。alpha.21 安装包保持不变，可用于回退。

回归覆盖真实 Pi AgentSession 的工具循环、拆分摘要、单次压缩及续行、失败暂停，以及取消、新指令和审批拒绝；发布流程还验证 Linux 身份、Kind 集群安装与推理、Host 安装和双架构归档。现场模型网关仍需验收：连续有界查询跨越阈值，观察压缩后继续原任务，再测试取消和失败时不自行续行。
