# InferNex Agent v0.5.0-alpha.18

修复 alpha.17 安装阶段 kubeconfig 发现与错误分类问题，并将 Dashboard 的部署配置视图对齐到推理工作负载。Host 安装继续使用 systemd，不要求执行 Helm install。

## 安装修复

首次安装区分配置文件缺失、配置无效以及 Kubernetes API 认证或连接失败。明确指定的配置不能在失败后静默切换到另一集群。升级时可复用已经安装的 Agent kubeconfig。安装器不会通过遍历其他用户目录或尝试 kubelet 身份来选择目标集群。

若目标集群的配置位于自定义路径，解压对应架构的包后运行：

```bash
sudo ./install.sh --admin-kubeconfig /实际路径/kubeconfig --dashboard-listen-address 0.0.0.0:8081
```

这里需要的是能够访问目标业务集群的 kubeconfig；推理服务的 values.yaml、Deployment YAML 或 Chart 模板不能代替 Kubernetes 连接凭据。现有现场报告只确认首次安装失败，尚未取得其实际配置路径及 API 连接结果，因此不能断言所有现场失败都来自同一个原因。

## Dashboard 中的部署配置

用户所需的配置是推理实例的模板、Helm 发布配置及资源规格。Agent 自身的 agent.conf 不是这些配置的替代品。

页面关联工作负载与 Helm release，并展示声明规模、就绪状态、镜像及资源配置。展开的 YAML 必须标明来源和裁剪范围：从 Kubernetes 读取的当前生效对象不等同于原始 Chart 模板或安装时传入的 values.yaml，也不是完整的可重新部署文件。

Kubernetes 通常不保存执行 `helm install -f` 时客户端文件的绝对路径。没有记录原始来源时，页面应明确标为未知；不能猜测路径，也不能将当前对象声称为原始文件。只读页面不显示 Secret 内容、环境变量值或认证信息。

SLO 实验结果表示批准的对照实验表现，不等同于持续采集的生产性能。完整版本历史、原始配置登记及生产流量升级仍需按各自能力边界验收。
