# InferNex Agent v0.5.0-alpha.17

本版修复 Host Dashboard 的外部访问和空页面问题，保留 alpha.16 的 SLO 对照实验、Git / snapshot 记录、Pi TUI 和诊断能力。

后续现场反馈：首次安装可能在 kubeconfig 发现阶段失败，错误信息未区分文件缺失与 API 连接失败；部署 YAML 展示也未完成。本版的 CI 仅证明测试环境通过，不代表现场安装已经验证。修复见[alpha.18 说明](https://github.com/lsjfy-open-com/infernex-agent/blob/develop/component/InferNex-Agent/docs/releases/v0.5.0-alpha.18-zh.md)。

## 修复内容

- Host 新安装默认通过 `http://<Host IP>:8081/` 访问 Dashboard，不再必须建立 SSH 隧道。显式监听地址优先，升级保留已有地址；MCP 与诊断子代理仍默认仅监听本机。
- Dashboard 补充原生 Kubernetes 工作负载概览，无需 InferNex Bridge。页面区分未启用 Bridge、没有匹配资源、数据读取失败与权限不足。
- 各数据区域独立更新，单个接口失败不会使其他区域空白。原生概览使用共享缓存，展示采集时间、范围及不完整状态。
- Dashboard 增加运行配置入口：显示 SLO 是否启用、profile 目录、Git/snapshot 版本记录目录和可用 profile 摘要；实验卡片显示当前阶段、实例基线/候选、p95、成功率、吞吐和证据摘要。
- 外部 Dashboard 提供只读摘要；详细诊断证据通过 Agent 的受控工具查看。页面不提供集群写操作，也不自动增加 Kubernetes 权限。

## 安装和升级

下载与管理节点 CPU 架构对应的安装包及 SHA-256 文件。保持已有安装参数；旧安装要改为 Host 直访，显式传入监听地址：

```bash
sha256sum --check infernex-agent-0.5.0-alpha.17-linux-*.tar.gz.sha256
tar -xzf infernex-agent-0.5.0-alpha.17-linux-*.tar.gz
cd infernex-agent-0.5.0-alpha.17-linux-*
sudo ./install.sh --dashboard-listen-address 0.0.0.0:8081
```

浏览器使用实际 Host IP，不使用 `0.0.0.0`。多网卡环境选择客户端能够路由到的地址；已有防火墙或安全组需允许该管理入口。也可显式绑定某个管理网 IP，或使用 `127.0.0.1:8081` 保留隧道访问。Dashboard 无内置登录，使用管理网访问控制或现有认证代理。

Host 安装不需要 Helm。只有将 Agent 自身安装为集群内 Deployment/Service，或接入已有 Gateway/NodePort 时才需要 Helm；Helm 不负责替换被观察的推理实例。

已有安装无需重装即可修改监听地址，但原生概览和页面状态修复需要升级二进制。步骤见[产品使用指南](https://github.com/lsjfy-open-com/infernex-agent/blob/develop/component/InferNex-Agent/docs/guides/product-guide-zh.md)。

## 能力边界

Dashboard 读取当前 kubeconfig 允许的范围，不将查询失败解释成集群没有资源。展示数量和列表受采集范围、缓存时间与截断限制；底层 Kubernetes 查询仍复用现有 reader，不能承诺与集群规模无关的查询成本。本版不增加生产实例升级、切流或完整自动回退能力。
