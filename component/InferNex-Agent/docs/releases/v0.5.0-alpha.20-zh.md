# InferNex Agent v0.5.0-alpha.20

alpha.20 交付 D1“规格与容量计划”的第一个只读切片：使用调用方提供的同构单实例 Profile、namespace 和 replicas，读取当前 Kubernetes 资源快照并估算可放置实例数。CLI 入口为 `infernex-agent deployment-plan --profile FILE --namespace NS --replicas N --kubeconfig FILE`；启用 Kubernetes 工具集时，MCP 提供 `k8s_plan_deployment`，接受内联 Profile 并返回相同的 Plan 结构。该能力不要求 InferNex Bridge。

Profile 明确区分单实例 CPU、内存和设备数与服务实例数。例如每实例 2 张卡、`replicas=3` 表示三个同规格实例共需 6 张卡，不会被解释成一个 6 卡实例。计划返回 `resource-fit`、`insufficient` 或 `blocked`，以及规范化资源估算、可放置实例数、节点放置估算、原因/警告、`profileHash`、`snapshotHash` 和绑定 namespace/replicas/两者的 `planHash`。认证、RBAC 读取或输入失败时拒绝生成 Plan；基础快照读取成功但遇到第一切片无法安全计算的复杂调度约束时，按 unknown 返回 `blocked`。两种情况都 fail closed。alpha.20 不自动新增或扩大 RBAC；默认 namespace-scoped host/Helm 身份通常不足，cluster-wide Helm 身份也可能缺少部分必要读取权限，应由现场管理员按指南提供已批准的最小读取身份。

本版只做规划。Plan 不是 Kubernetes 资源、资源预留、管理员批准、调度承诺或性能证明；`trafficVerified`、`performanceVerified` 和 `reservationCreated` 均为 `false`。规划器不创建 Deployment、Service 或任意 YAML，不扩缩容，不自动改写 Profile，也不支持在一个计划中混合异构 Profile。它没有量测吞吐、TTFT、TPOT、并发、成功率或其他业务 SLO。完整 D1 仍需补齐更多调度、拓扑、配额和硬件现场边界，D2 原生写路径仍未交付。

可直接由 CLI 读取的 JSON 示例使用示例域名和虚构镜像摘要，只用于说明输入格式；它不是可部署制品、批准配置或性能基线。操作步骤、字段解释和 fail-closed 边界见[部署规格资源规划指南](https://github.com/lsjfy-open-com/infernex-agent/blob/develop/component/InferNex-Agent/docs/guides/deployment-planning-zh.md)。

alpha.20 保留 alpha.19 的无参数 kubeconfig 自动发现：普通用户仍可运行 `sudo ./install.sh`，已经是 root 时运行 `./install.sh`。它也保留 Host Dashboard 实时 YAML、SLO 对照实验和 Git/snapshot 追溯能力，边界不变。

alpha.20 安装包尚待 Release CI 构建与校验；GPU/NPU、设备插件、拓扑和客户权限模型仍待现场验证。发布页出现归档及对应 SHA256 后，才可按[离线安装指南](https://github.com/lsjfy-open-com/infernex-agent/blob/develop/component/InferNex-Agent/docs/guides/offline-install-zh.md)下载验证。当前文档和单元/集成测试结果不能替代硬件现场验收。
