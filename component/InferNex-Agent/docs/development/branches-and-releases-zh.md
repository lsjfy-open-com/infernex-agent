# 分支与发布

## 保留两条长期线

| 名称 | 用途 |
| --- | --- |
| `main` | 历史已合并基线；开发基线的整体晋级由单一 Draft PR 跟踪，不能误称现有实验版已经合入 |
| `develop` | 唯一日常开发和功能集成基线，从 alpha.13 完整源码建立；仓库默认分支 |
| `core/*`、`deploy/*`、`ops/*`、`traffic/*`、`adapter/*`、`docs/*` | 从 develop 开始的短期工作分支，一个 PR 一个可验收范围，合入 develop 后删除 |
| `infernex-agent-v<version>` tag | 不可变的已发布源码，与 Release 附件对应；不以长期 release 分支维护每个实验包 |

历史 #8、#9、#10、#14、#15 的全部提交保存在 alpha.13 tag 和 develop；保留其讨论和 diff，通过替代说明关闭，不伪称已合并 main。对应旧远端分支仅在确认完整包含于保留基线、PR 已关闭后删除。没有保留的新提交禁止清理。

不再让新的业务工作堆叠在五层历史候选分支上。必要的短期堆叠只引用直接依赖；新代码从 develop 创建分支。`main` 的基线晋级与原生/Bridge/硬件各项验收分别列明，不以实验 Release 发布代替 PR 合并。

## 实验包

1. 选择干净的已验证集成提交，版本唯一；不覆盖已发布 tag 或附件。
2. 跑全量 Agent/Kind CI，打包时显式开启完整 Pi；保留源码 SHA、版本与依赖固定摘要。
3. 验证双架构归档、内部 SHA256、架构、Pi/rg/fd/Skills 和安装入口；仅发布两份包和两份校验文件。
4. Release notes 写清相对上版的行为变化、功能保留、兼容性、自动验证和仍需现场验证的环境。
5. 实验版可以供现场验收使用，必须标记 prerelease；现场未验收不能冒充稳定版或某硬件 Profile 已获验证。

alpha.13 已发布且保持不变；本次 K0 改动先经 PR/CI 集成，不暗中改写该安装包。
