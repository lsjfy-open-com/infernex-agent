# 候选与发布验收

alpha.13 已作为实验预发布提供完整双架构 Pi 安装包。它包含 #10/#14/#15 的代码，但不表示历史 Draft PR 已合入 main。本页取代旧文档中“公开版本仍是 0.3.0”的过期描述。

## 按能力验收

| 路径 | 自动化最低要求 | 现场证据 |
| --- | --- | --- |
| 通用 Kubernetes 只读能力 | 无 Bridge 的工具注册、权限/namespace 限制、原生对象读取与错误报告 | 客户实际 kubeconfig、资源发现与取证 |
| 原生自动部署和请求均衡 | 在 D1/D2/T1 实现后，跑无 Bridge Kind 规格计划、创建/回退、真实入口多后端与长连接测试 | 相应运行 Profile 的模型/硬件/网络 |
| Bridge 部署与恢复 | 源/目标身份、配置漂移、批准失效、持久日志、真实 Kind 回退 | 既有 InferNex/A2 集群兼容与回退 |
| Pi 与安装包 | 固定 runtime/rg/fd 摘要、扩展测试、双架构打包、内外 SHA256、安装/升级和恢复点 | 目标 CPU/OS、真实模型接口与 tool calling |

通用核心不以安装 InferNex 为前置条件；CPU Kind 通过也不能替代 Ascend/CANN/RDMA 验收。客户 Operator 管理的对象必须走其适配器，不能为通过验收直接改子 Deployment。

## 实验环境操作

1. 下载所测固定版本对应架构的归档与 SHA256，校验后安装。
2. 确认 `version --json`、当前 kubeconfig/context、目标业务集群和模型接口。
3. 先做通用发现、工作负载/事件/日志读取。新开发工具只在包含该代码的新构建中存在，不能拿 alpha.13 测尚未发布的 K0 工具。
4. 验证 Service 的逐端口就绪后端、ClientIP/Local 策略和实际入口。配置诊断不是请求均衡通过。
5. 只在已启用的部署适配器上批准测试实例；检查创建、Ready、真实推理和失败回退，分别记录结果。
6. 检查重启恢复、安装恢复点、证据和变更记录；核对敏感信息不进入日志。

## 发布记录

实验预发布用于上述现场测试，明确标记 prerelease、功能范围和未验证环境。稳定晋级及 main 基线合并须有明确验收记录，不能用“包已发布”替代。发布只提供 amd64/arm64 两份普通 Agent 归档及两份 SHA256；主干开发与不可变版本的关系见[分支与发布](branches-and-releases-zh.md)。
