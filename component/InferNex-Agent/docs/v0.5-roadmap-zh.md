# InferNex Agent v0.5 可执行路线图

状态标记：`[x]` 已实现并有测试；`[~]` 已有纵向切片但未完成现场验收；`[ ]` 尚未实现。
每项只在代码、测试、文档和对应环境验收都满足时改为 `[x]`。

## M0：提案和主仓合入边界

- [x] Agent Core 保持在 `component/InferNex-Agent`，不复制 InferNex controller/CRD。
- [x] Pi 作为可替换 Experience/Runtime，Go Core 持有工具、安全和持久状态。
- [x] 写明通用 Agent、Skill 与 InferNex 专用 Agent/MCP 的差异及可组合关系。
- [x] 建立当前/计划 MCP tool catalog，禁止文档把计划能力写成已实现。
- [ ] 在 InferNex 主仓建立正式 issue/milestone，并由维护者确认组件 owner 和合入提交序列。
- [ ] 每个 RC 记录相对上游 master 的依赖、权限、构建和默认行为差异。

## M1：可靠交互、上下文与输出

- [x] OpenAI-compatible timeout、有界 retry、空消息识别、tool loop 阻断。
- [x] 长工具结果 Artifact + SHA-256 + 渐进读取。
- [x] 运维人员历史日志 allow-list、glob、grep、分页读取、可解释探针噪声过滤和持久 Markdown 报告。
- [x] 内置 CANN Runtime、HiXL/LLM DataDist 诊断 Skill，以及受控用户 Skill 安装与渐进读取。
- [x] classic chat 自动压缩、usage/context 状态和 `finish_reason=length` 自动续写。
- [x] Pi TUI 首事件等待、streaming 状态、provider error 和空响应可见。
- [x] `max-output-tokens` 写入安装配置并由 classic/Pi 共用；默认 8192（小窗口按 1/4 降低）。
- [x] 交互配置模型时询问真实 context window 和单次输出上限。
- [ ] 从 endpoint capability probe 自动建议 context/output，而不是替用户擅自扩大。
- [ ] GLM 5.x、Qwen 3.x、vLLM-Ascend parser 矩阵现场验收。
